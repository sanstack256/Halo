## 1. Executive Summary & Resolution of §3.1

In accordance with Phase 8 Master Engineering Manual §3 and §3.1, we audited the metric-producing code in:
1. `apps/dashboard/src/lib/investigation/recommendation-engine/__tests__/evaluation/decomposed-benchmark-evaluator.ts` (lines 196–205)
2. `scripts/evaluate-phase7-engine.ts` (lines 190–220)

### Resolution of §3.1: Does `105 / 105` mean A, B, or C?

**Finding: It means B and C (conflation of evaluator knowledge and non-code inaction).**

In `decomposed-benchmark-evaluator.ts`:
```typescript
// 13. Patch Behavioral Correctness
const patchBehaviorallyCorrect = truth.shouldModifyCode
    ? patchApplied && patchStructurallyCorrect && invariantRestored
    : !rec.isCodeModification;
```

And in `scripts/evaluate-phase7-engine.ts`:
```typescript
const isBehaviorallyEffective = score.patchBehaviorallyCorrect && score.invariantRestored;
if (isBehaviorallyEffective) totalRepairBehaviorallyEffective++;
```

The audit reveals two conflations in Phase 7 reporting:
1. **Evaluator Structural Truth Conflated with Runtime Execution:** For code-modification scenarios (84), `patchBehaviorallyCorrect` evaluated whether `patchApplied && patchStructurallyCorrect && invariantRestored` held true according to the scenario's static contract and patch diff. It did **not** mean that Halo's empirical execution environment ran a live test. Halo's actual empirical execution proof in Phase 7 was **52 / 105 (49.5%)**.
2. **Non-Code Incidents Counted as Behaviorally Effective:** For non-code incidents (21 scenarios involving external outages, missing env vars, rollbacks, and pool leaks), `!rec.isCodeModification` evaluated to `true`, crediting them as "behaviorally correct" even though no code patch or execution occurred.

## 2. Separation of Evaluator Truth from Halo Proof (§3.1, §4)

To prevent evaluator leakage and eliminate conflation, Phase 8 establishes two strictly separated metric hierarchies:

### A. Evaluator-Side Ground Truth Knowledge (Oracle Horizon)
These metrics measure what the benchmark oracle knows about the repository state:
* `evaluatorKnownRepairEffectiveness`: 105 / 105 (Oracle knows the intended remediation across all 105 scenarios)
* `evaluatorCodeIncidents`: 84 / 105
* `evaluatorNonCodeIncidents`: 21 / 105

### B. Halo Empirical Proof Funnel (Hermetic Execution Horizon)
These metrics measure only what Halo autonomously proved through hermetic sandbox execution:
* `candidateGenerated`: Candidates generated by Halo's search engine.
* `candidateAcceptedForExecution`: Candidates that passed preliminary semantic constraints.
* `patchGenerated`: Concrete unified diff / replacement code synthesized.
* `patchApplied`: Patch applied cleanly to real source files in isolated sandbox.
* `patchCompiles`: Source compiles without type or syntax errors after patching.
* `baselineReproduced`: Original failure reproduced in sandbox before patch application.
* `failureRemoved`: Original failure signature ceases to trigger after patch application.
* `behaviorValidated`: Post-patch execution completes cleanly and matches expected behavior.
* `invariantValidated`: Governing invariant verified intact via runtime assertion or contract check.
* `regressionValidated`: Regression test suite executed and passed without collateral failures.
* `counterexamplesValidated`: Controlled perturbations and counterexamples evaluated and survived.
* `fullyVerified`: Unanimous approval by fail-closed `verified-repair-gate.ts`.
